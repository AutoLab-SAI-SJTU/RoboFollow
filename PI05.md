# π0.5: conversion, training and evaluation / 转换、训练与评测

Run commands from the RoboTwin root. The simulator and model use separate Python environments. Training uses OpenPI at `XPolicyLab/policy/Pi_05/openpi`.

以下命令在 RoboTwin 根目录执行。仿真与模型使用独立的 Python 环境，训练器位于 `XPolicyLab/policy/Pi_05/openpi`。

## 1. Model environment / 模型环境

Install `uv`, initialize XPolicyLab, and run:

安装 `uv` 并初始化 XPolicyLab 后执行：

```bash
git submodule update --init --recursive
bash robofollow/setup_pi05.sh
MODEL_PYTHON="$PWD/XPolicyLab/policy/Pi_05/openpi/.venv/bin/python"
export HF_LEROBOT_HOME="$PWD/data/lerobot"
export OPENPI_DATA_HOME="$PWD/data/openpi-cache"
export JAX_COMPILATION_CACHE_DIR="$PWD/data/jax-cache"
```

`UV_PROJECT_ENVIRONMENT` can select a different **absolute** environment path; set `MODEL_PYTHON` to its `bin/python` in that case. Proxy variables, when needed, must be exported in the shell (`HTTP_PROXY`, `HTTPS_PROXY`). The first run downloads the public PaliGemma tokenizer in addition to the base weights.

可用 `UV_PROJECT_ENVIRONMENT` 指定独立环境的**绝对路径**，此时相应修改 `MODEL_PYTHON`。需要代理时，在 shell 中导出 `HTTP_PROXY` 和 `HTTPS_PROXY`。首次运行还需要下载公开的 PaliGemma tokenizer；基础权重目录不包含该文件。

The OpenPI lock pins NumPy to 1.26.4, which conflicts with the optional Rerun viewer’s NumPy >=2 requirement. The installer allows this specific conflict and checks all other dependencies. Training does not use Rerun. The installer also adds `pytest`, which OpenPI imports at runtime.

OpenPI 锁文件固定 NumPy 为 1.26.4，与可选 Rerun 查看器要求的 NumPy >=2 冲突。安装器允许这一项冲突，其余依赖仍执行检查。训练不使用 Rerun。安装器同时安装 OpenPI 运行时需要的 `pytest`。

## 2. Collect and convert / 采集与转换

Use the simulator Python for collection (see the main README), then switch to the model interpreter for conversion:

采集使用主 README 中的仿真环境；转换使用模型环境：

```bash
python -m robofollow.collect \
  --scene scene1 --tasks pickup_yellow_block_1_left \
  --episodes 3 --max-seed-attempts 30 --gpu 0 \
  --output data/robofollow_pi05_raw

"$MODEL_PYTHON" -m robofollow.lerobot_convert \
  --input data/robofollow_pi05_raw \
  --output "$HF_LEROBOT_HOME/robofollow/scene1-smoke" \
  --repo-id robofollow/scene1-smoke
```

The LeRobot output directory must not exist. Conversion pairs raw frames once, retains existing state/action pairs, and decodes RGB with RoboTwin’s decoder. Images are resized to 640 × 480; use `--image-width` and `--image-height` to change the size. Each training instruction variant gets a copy of the trajectory. Use `--first-instruction-only` to keep one instruction per episode.

LeRobot 输出目录必须不存在。转换对原始帧配对一次，对已有 state/action 数据保留配对，并使用 RoboTwin 解码器读取 RGB。图像默认缩放为 640 × 480，可用 `--image-width` 和 `--image-height` 设置。每个训练指令变体对应一份轨迹；添加 `--first-instruction-only` 可使每条 episode 只保留一条指令。

LeRobot uses FPS to index action chunks. The default is 17, approximating 250 Hz physics with observations saved every 15 simulation steps. Conversion preserves the samples without resampling; evaluation uses TOPP timing.

LeRobot 使用 FPS 索引动作片段。默认值为 17，对应 250 Hz 仿真每 15 步保存一次观测的近似采样率。转换保留原始采样；评测时序由 TOPP 决定。

## 3. Normalization and short training / 归一化与短程训练

Use your downloaded `pi05_base` directory, which must contain `params/`. Keep the configuration identical for statistics, training and inference:

使用已下载且包含 `params/` 的 `pi05_base` 目录。统计、训练和推理配置须一致：

```bash
PI05_BASE=/absolute/path/to/pi05_base
COMMON=(
  --repo-id robofollow/scene1-smoke
  --base-weights "$PI05_BASE"
  --run-dir "$PWD/checkpoints/robofollow-smoke"
  --steps 20 --batch-size 8 --fsdp-devices 4 --num-workers 0 --save-interval 1000
)
JAX_PLATFORMS=cpu CUDA_VISIBLE_DEVICES='' \
  "$MODEL_PYTHON" -m robofollow.pi05 stats "${COMMON[@]}"
CUDA_VISIBLE_DEVICES=0,1,2,3 XLA_PYTHON_CLIENT_MEM_FRACTION=0.9 \
  "$MODEL_PYTHON" -m robofollow.pi05 train "${COMMON[@]}"
```

Training updates all model parameters. OpenPI uses delta joint actions and absolute gripper actions; inference converts joint actions back to absolute targets. `adapt_to_pi=False` preserves RoboTwin’s joint convention. Normalization statistics are computed from the selected training data.

训练采用全参数微调，关节动作在模型内部使用增量，夹爪使用绝对值；推理时将关节动作还原为绝对目标。`adapt_to_pi=False` 保持 RoboTwin 的关节约定。归一化统计量由所选训练数据计算。

The run directory contains `train_config.json`, normalization assets, and `checkpoints/<step>/`. With 20 steps, the final OpenPI checkpoint is numbered `19` (zero-based). `--resume` explicitly continues an existing run; outputs are never overwritten by default. More steps can be requested with `--steps`.

运行目录包含配置清单、归一化数据和 `checkpoints/<step>/`。20 步训练的最终 checkpoint 编号为 `19`（从 0 开始）。续训显式添加 `--resume`，默认不会覆盖已有 checkpoint；实际训练可增加 `--steps`。

## 4. Serve and evaluate / 服务与评测

Start the policy in the model environment:

在模型环境启动服务：

```bash
CUDA_VISIBLE_DEVICES=4 XLA_PYTHON_CLIENT_PREALLOCATE=false \
  "$MODEL_PYTHON" -m robofollow.serve \
  --factory robofollow.pi05:Pi05Policy \
  --kwargs '{"checkpoint":"checkpoints/robofollow-smoke/checkpoints/19"}' \
  --host 127.0.0.1 --port 8999
```

In another terminal, use the simulator environment:

另一终端使用仿真环境：

```bash
python -m robofollow.evaluate \
  --scene scene1 --levels L0 --limit 1 --rounds 1 \
  --max-steps 10 --actions-per-step 50 --gpu 0 \
  --runtime fixed \
  --remote --host 127.0.0.1 --port 8999 --policy-timeout 300 \
  --output results/robofollow_pi05_smoke --video
```

The adapter reads `train_config.json` from the run directory. Use `config_path` to specify another location. Evaluation writes episode details to `results.json`, aggregates to `summary.json`, and videos to `videos/`.

适配器从训练运行目录读取 `train_config.json`，也可通过 `config_path` 指定位置。评测结果保存在 `results.json`，汇总指标保存在 `summary.json`，视频位于 `videos/`。

For externally trained checkpoints, supply the training manifest through `config_path`. Its `repo_id`, camera transforms, and action transforms must match the checkpoint. For a checkpoint with LoRA on both components, set `paligemma_variant` to `gemma_2b_lora` and `action_expert_variant` to `gemma_300m_lora`. Omitting these fields selects the full-parameter architecture used by the training example above.

加载其他流程训练的 checkpoint 时，通过 `config_path` 提供训练配置，其中的 `repo_id`、相机变换和动作变换需与 checkpoint 匹配。若两个组件均使用 LoRA，设置 `paligemma_variant: "gemma_2b_lora"` 和 `action_expert_variant: "gemma_300m_lora"`；省略时使用上述训练示例的全参数结构。

Evaluation uses `--runtime fixed`. The action budget is controlled by `--max-steps` and `--actions-per-step`; expert success checks do not stop execution early.

评测统一使用 `--runtime fixed`。动作预算由 `--max-steps` 和 `--actions-per-step` 控制，专家成功判定不会提前停止动作。
